## Post-optimisation benchmarks — 2026-05-27

### Optimisations applied (in two sessions)

**Session 1 (2026-05-26):**
- Fixed 7 bugs (mutable default arg, double captain 2×, duplicate check, off-by-one, swap crash, etc.)
- Refactored `team.py` 1705 → ~700 lines
- Extracted `fpl_auto/predictor.py` (pluggable ML model)
- Added `_fixtures_cache` — eliminated 19,498 CSV reads per season
- Added `_gw_cache` — eliminated redundant per-GW CSV reads
- Added `multiprocessing.Pool` parallel multi-season runs via `-seasons`

**Session 2 (2026-05-27):**
- Module-level `fpl_data` instance cache (`get_fpl_data`) — single instance shared across all 38 GW iterations per season; `_gw_cache`, `_fixtures_cache`, and `_prediction_cache` now persist for the whole run
- `_prediction_cache` — cached 4 TSV reads per GW (was 152 reads/season)
- `_recent_gw` cache — eliminated 38 HTTP requests per season (one HTTP call or exception, then cached)
- Vectorised `post_model_weightings` — pre-compute fixture adjustments for 20 teams once per GW instead of per-player pandas filtering (was 19,152 filter ops/season)
- Vectorised `discount_next_n_gws` — replaced broken `iterrows` write-back with numpy `stack` + broadcast (also fixed a latent bug where scalar xP was never written back, meaning multi-GW discounting was silently not applied)
- Sorted fixtures.csv on cache load — `head(N)` now reliably returns chronologically next N fixtures
