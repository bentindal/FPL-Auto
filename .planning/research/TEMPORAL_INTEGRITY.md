# Temporal Integrity in FPL-Auto Backtesting

**Research Date:** May 27, 2026  
**Domain:** Backtesting fairness, data access patterns, lookahead bias prevention  
**Confidence:** MEDIUM (Architecture verified from codebase; FPL API timing partially verified from current sources, partially from training knowledge)

## Summary

Temporal integrity in FPL backtesting requires strict enforcement that the strategy **only uses data available at the decision point**. FPL-Auto's current implementation has **significant lookahead bias vulnerabilities** that allow strategies to "cheat" by accessing future form, injury status, and price information.

The core issue: data CSVs in `data/{season}/gws/` are loaded and cached with no temporal boundaries. A strategy can read GW38 data while deciding transfers for GW1. Price changes, injury news, and fixture information are all available synchronously instead of respecting real-world release timing.

**Primary recommendation:** Implement a `TemporalGate` class that intercepts all data access calls and enforces `accessed_at <= decision_point`. Violations should raise `TemporalViolationError` with a trace of the violation (what data, when accessed, when available).

## 1. FPL Real-World Timing (Data Availability)

### Gameweek Deadline
- **Deadline time:** 90 minutes before the first match of the gameweek [VERIFIED: postman.com FPL API docs]
- **Typical schedule:** 
  - 10:30am UTC: deadline (if first match is 12:00 noon)
  - 12:00-3:00pm UTC: matches played (fixtures execute)
  - 2:30am UTC *next day*: price updates [VERIFIED: fpledits.com]
- **Critical rule:** Changes made after deadline apply to *next* gameweek, not current [VERIFIED: postman.com]

### Player Data Timeline (What is Known When)

| Data Point | Release Time | Available To Strategy | Notes |
|-----------|--------------|----------------------|-------|
| **Fixture list (full season)** | Pre-season (~Aug 1) | GW1 onwards | No changes; permanent from start of season |
| **Current player form** | After each match (~4-6 hours) | Next deadline (90 min before next GW) | Historical data shows results; future form unknowable |
| **Injury news** | Continuously (press conferences, official updates) | As it breaks, live to FPL API | *Off-limits*: future injuries are unknown |
| **Player price** | 2:30am UTC daily | Today's new price onwards | Can be predicted for tomorrow but not guaranteed |
| **Gameweek points** | ~2 hours after match ends | Only after match (not before decision for that GW) | Used in post-GW analysis only |

**Critical distinction:** FPL form data is "stale by design"—it shows what happened, not what will happen.

## 2. FPL-Auto's Data Access Architecture

### Where the Problem Exists

**File:** `fpl_auto/data.py`, `FplData` class

```python
# Lines 54-69: get_gw_data() with caching
def get_gw_data(self, season, week_num):
    cache_key = (season, week_num)
    if cache_key in self._gw_cache:
        return self._gw_cache[cache_key]
    
    gw_data = pd.read_csv(f'{self.data_location}/{season}/gws/gw{week_num}.csv')
    gw_data = gw_data[['name', 'position', 'team', ..., 'total_points', ...]]
    self._gw_cache[cache_key] = gw_data
    return gw_data
```

**The vulnerability:** Code executing for GW10 can call `get_gw_data(season, 38)` and instantly get all remaining season data. No temporal enforcement.

## 3. Safe Data Access Patterns (What is Safe to Access at Each Point)

### At Decision Time for Gameweek N (Before Deadline)

**Safe to access (all available at real deadline):**
- ✅ All historical form: GW1 through GW(N-1) actual points
- ✅ All fixture metadata: team_h, team_a, difficulty, event number (full season)
- ✅ Current player metadata: position, team (from latest GW data snapshot)
- ✅ Current prices: refreshed at 2:30am UTC, so GW deadline midnight → known prices
- ✅ Pre-trained predictions for GW(N): generated overnight, available by deadline
- ✅ Multi-GW discounting: fixture adjustments for GW(N+1...N+5) are valid because fixtures are known

**NOT safe to access (unknown at deadline):**
- ❌ Actual points for GW(N): match results not yet known
- ❌ Future injury status: may change between now and next deadline
- ❌ Future form changes: next GW outcomes unknown
- ❌ Price changes for GW(N+1): determined by real transfer volumes post-deadline
- ❌ Player transfers between clubs: won't happen mid-gameweek

### At Resolution Time for Gameweek N (After Matches Complete)

**New data now available:**
- ✅ Actual points for GW(N): matches completed
- ✅ Updated player status: confirmed injuries, position changes
- ✅ Bench/substitution decisions: who played, who didn't
- ✅ New predictions for GW(N+1): can be trained on up-to-date GW(N) actual results

**When reading this data for scoring/analysis:**
- Must be labeled as `actual_points_for_gw(gw)` when reading post-GW
- Strategy decisions for GW(N) must never see this data
- Predictions generated pre-GW must not use GW(N) actual points

## 4. Identified Temporal Violations in FPL-Auto

### Violation 1: Model Training Uses Current-GW Data

**Location:** `model.py`, lines 56-61  
**Severity:** HIGH

```python
for i in range(target_gameweek, min(target_gameweek + repeat, 39)):
    training_data, test_data = vastaav.get_training_data_all(season, i - training_prev_weeks, i)
    # Trains on GW(i-19) through GW(i), predicts GW(i)
    predictor = Predictor(model_type=inputs.model).fit(training_data)
    player_names, predictions = vastaav.get_player_predictions(season, i - predict_weeks, i, predictor.models)
```

**Problem:** Trains using data from GW(i) (including its actual points) to predict GW(i). The features for that week include the outcome you're trying to predict.

**Fix:** Train on `i - training_prev_weeks - 1` to `i - 1` (exclude current GW from training).

**Code change:**
```python
# BEFORE
training_data, test_data = vastaav.get_training_data_all(season, i - training_prev_weeks, i)

# AFTER
training_data, test_data = vastaav.get_training_data_all(season, i - training_prev_weeks - 1, i - 1)
```

## 5. Encoding Temporal Boundaries in Code (Prevention Patterns)

### Pattern 1: Explicit Temporal Gate (High Assurance)

**What:** A class that intercepts all data access and enforces temporal rules.

```python
class TemporalGate:
    """
    Enforces temporal integrity: no future data access during backtesting.
    
    Raises TemporalViolationError if:
    - A decision-time method tries to read data beyond decision_gameweek
    - A post-GW analysis tries to read data from wrong semantic context
    """
    
    def __init__(self, season: str, decision_gameweek: int):
        self.season = season
        self.decision_gameweek = decision_gameweek
        self.data_accessed = []  # For audit trail
    
    def safe_read_historical_form(self, gw_data_csv_path: str, target_gw: int) -> pd.DataFrame:
        """Read past form. Allows up to decision_gameweek - 1."""
        if target_gw >= self.decision_gameweek:
            raise TemporalViolationError(
                f"Trying to access GW{target_gw} actual points during decision for GW{self.decision_gameweek}. "
                f"Only GW1-{self.decision_gameweek - 1} available."
            )
        data = pd.read_csv(gw_data_csv_path)
        self.data_accessed.append(('historical_form', target_gw, self.decision_gameweek))
        return data
    
    def safe_read_predictions(self, pred_tsv_path: str, gw: int) -> pd.DataFrame:
        """Read pre-trained predictions. Only for current GW."""
        if gw != self.decision_gameweek:
            raise TemporalViolationError(
                f"Predictions for GW{gw} accessed during GW{self.decision_gameweek} decision. "
                f"Only predictions for GW{self.decision_gameweek} should be needed."
            )
        data = pd.read_csv(pred_tsv_path, sep='\t')
        self.data_accessed.append(('predictions', gw, self.decision_gameweek))
        return data
    
    def safe_read_fixture_metadata(self, fixtures_csv_path: str) -> pd.DataFrame:
        """Fixture list is fully known pre-season, always safe."""
        data = pd.read_csv(fixtures_csv_path)
        self.data_accessed.append(('fixtures_metadata', None, self.decision_gameweek))
        return data

class TemporalViolationError(Exception):
    """Raised when a temporal boundary is violated."""
    pass
```

**Usage in `Team.__init__`:**
```python
def __init__(self, season, gameweek=1, ...):
    self.fpl = fpl.get_fpl_data('data', season)
    self.temporal_gate = TemporalGate(season, gameweek)  # NEW
    
    # Replace: self.gw_data = self.fpl.get_gw_data(season, gameweek)
    # With:
    self.gw_data = self.temporal_gate.safe_read_historical_form(
        f'data/{season}/gws/gw{gameweek - 1}.csv', 
        gameweek - 1
    )
```

### Pattern 2: Data Versioning with Timestamps

**What:** Tag every data fetch with `available_as_of` timestamp; verify it's ≤ decision time.

```python
@dataclass
class TemporalSnapshot:
    """Data bound to a specific point in time."""
    season: str
    gameweek: int
    data: pd.DataFrame
    available_as_of: datetime  # When this data became known
    
    def validate_access(self, decision_time: datetime) -> bool:
        """Verify this data was available when the decision was made."""
        return self.available_as_of <= decision_time

# Usage:
gw_data = TemporalSnapshot(
    season='2023-24',
    gameweek=10,
    data=df,
    available_as_of=datetime(2024, 1, 15, 14, 30)  # 90 min before GW10 kicks off
)

# In Team.__init__:
if not gw_data.validate_access(self.decision_deadline):
    raise TemporalViolationError(...)
```

### Pattern 3: Separation of Concerns (Pre-GW vs Post-GW)

**What:** Different data classes for decision-time and scoring-time.

```python
class PreGameweekDataset:
    """Provides only data available before deadline."""
    def __init__(self, fpl_data, gameweek):
        self.gameweek = gameweek
        self.fpl = fpl_data
    
    def get_past_form(self, target_gw: int) -> pd.DataFrame:
        """Historical points from GW 1 to GW(gameweek-1)."""
        if target_gw >= self.gameweek:
            raise ValueError(f"Cannot access GW{target_gw} before GW{self.gameweek} deadline")
        return self.fpl.get_gw_data(self.fpl.season, target_gw)
    
    def get_current_predictions(self) -> pd.DataFrame:
        """Pre-trained predictions for this gameweek only."""
        return self.fpl.get_predictions(self.gameweek, 'GK')  # etc

class PostGameweekDataset:
    """Provides actual outcomes after matches complete."""
    def __init__(self, fpl_data, gameweek):
        self.gameweek = gameweek
        self.fpl = fpl_data
    
    def get_actual_points(self) -> dict:
        """Actual points from completed gameweek only."""
        return self.fpl.actual_points_dict(self.fpl.season, self.gameweek)
```

**Usage in manager.py:**
```python
for gw in range(start_gw, start_gw + repeat + 1):
    # Decision phase
    pre_gw = PreGameweekDataset(fpl_data, gw)
    t.auto_transfer()  # Uses pre_gw internally
    t.auto_subs()
    
    # Scoring phase (after matches)
    post_gw = PostGameweekDataset(fpl_data, gw)
    actual_points = post_gw.get_actual_points()
```

## 8. Summary: Safe Backtesting Checklist

To ensure temporal integrity in future modifications:

- [ ] **Before GW decision:** Can only read GW 1 to GW(N-1) actual points
- [ ] **Before GW decision:** Can only read predictions for GW(N) (pre-trained)
- [ ] **Before GW decision:** Can only read fixture metadata (full season, known pre-season)
- [ ] **Model training:** Never includes actual points from the GW being predicted
- [ ] **Predictions:** Pre-generated and stored before season run begins
- [ ] **Actual points:** Only read after matches complete; never during decision
- [ ] **Multi-GW lookahead:** Intentional for strategy; never mixed into actual point calculations
- [ ] **Price changes:** Acknowledged as unknown (not used in this codebase)
- [ ] **Injury updates:** Treated as unknown (not incorporated in decisions)
