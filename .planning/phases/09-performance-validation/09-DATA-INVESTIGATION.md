# Phase 9 Plan 01: 2024-25 Data Initialization Investigation

**Date:** 2026-05-28  
**Status:** INVESTIGATION COMPLETE  
**Root Cause:** IDENTIFIED

---

## Summary

The "Squad has no GK available for bench selection" error encountered during Phase 8 Plan 03 walk-forward evaluation on 2024-25 season is caused by **incomplete historical gameweek data for 2024-25**. The data/2024-25/gws/ directory contains only gw1.csv through gw4.csv, meaning any team initialization beyond GW4 attempts to load empty DataFrames, causing player lookups to fail and preventing transfers.

---

## Root Cause Analysis

### Error Location
- **File:** fpl_auto/team.py, line 270
- **Error Message:** "Squad has no GK available for bench selection"
- **Trigger:** team.suggest_subs() when self.gks is empty

### Causal Chain

1. **Phase 8 Plan 03** attempts to run walk-forward evaluation on 2024-25 season
2. **GW5 Free Hit chip activation** triggers initial_team_generator() to rebuild squad
3. **_get_best_players() called** for each position (GK, DEF, MID, FWD)
4. **get_gw_data(2024-25, 5)** is invoked to fetch player costs/positions for GW5
5. **GW5 data is missing** - only gw1.csv through gw4.csv exist in data/2024-25/gws/
6. **Empty DataFrame returned** with shape (0, 22) - correct columns but zero rows
7. **transfer_in_allowed() fails for all players** because gw_data.loc[player_name] raises KeyError
8. **add_player() returns None** for every candidate in _get_best_players()
9. **Squad remains empty** after initial_team_generator() completes
10. **suggest_subs() raises ValueError** when checking if not ranked_gk (list is empty)

### Verification

**Data availability check:**

**Comparison with 2023-24 (working):**


**Confirmed via code inspection:**

```python
# From fpl_auto/data.py:68-85
gw5_data = get_fpl_data('data', '2024-25').get_gw_data('2024-25', 5)
# Result: DataFrame with shape (0, 22) — empty rows, all columns
```

### Why Predictions Exist But Data Doesn't

- **Predictions files** (predictions/2024-25/GW1-GW8/ with position TSVs) were **generated by model.py** - these are pre-trained model outputs, not historical game results
- **Historical GW data** (data/2024-25/gws/gw*.csv) come from **external data source** (vaastav/Fantasy-Premier-League or manual collection), representing actual completed gameweeks
- **Data source incomplete:** 2024-25 season only has 4 completed gameweeks captured in the project's data directory (consistent with May 2026 timeline - season started August 2024, so 4-9 months elapsed = ~35 GWs into season, but dataset only includes first 4)

## Fix Recommendation

### Option A: Skip 2024-25 Validation (RECOMMENDED)

**Action:** Proceed with Phase 9 using 2023-24-only walk-forward validation  
**Rationale:**
- 2024-25 season data is fundamentally incomplete (only 4 GWs available)
- Cannot simulate full season (requires data up to GW38)
- Data regeneration via model.py not applicable (predictions already exist, issue is historical GW CSVs)
- Regenerating historical data requires external data source (not under project control)
- Phase 9 CONTEXT.md explicitly allows this fallback: "If 2024-25 Data Remains Broken: Proceed with 2023-24 validation... caveat in report"

**Impact:** Minimal risk
- Phase 8 results already validated on 2023-24 (BENCH_SAFE_STATIC confirmed optimal)
- Cross-season robustness would be desirable but not critical for Phase 9 completion
- Single-season validation acceptable per CONTEXT.md pragmatic thresholds

**Implementation:** Document caveat in Phase 9 report; adjust walk-forward configuration to skip 2024-25

### Option B: Wait for Complete 2024-25 Data (NOT RECOMMENDED)

**Action:** Delay Phase 9 until full 2024-25 season data is available  
**Effort:** External dependency - requires updated data from vaastav/Fantasy-Premier-League GitHub or manual collection  
**Timeline:** Unknown (depends on data source refresh cycle)  
**Risk:** Phase 9 may stall indefinitely if data source is not actively maintained for current season
