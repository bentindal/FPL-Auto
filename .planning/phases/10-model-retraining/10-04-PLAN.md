  <name>Task 3: Write operational runbook</name>
  <files>docs/RETRAINING_RUNBOOK.md</files>
  <action>
Create docs/RETRAINING_RUNBOOK.md with comprehensive operational guide.

Sections:

1. Overview
   - Purpose: Scheduled model retraining every 2 GWs + drift-driven override
   - Frequency: 2-GW schedule (GW 2, 4, 6, ..., 38)
   - Orchestration: Apache Airflow DAG (fpl_retrain_schedule)
   - Schedule: Tue-Sun 19:00 UTC (post-match window)

2. Prerequisites
   - Airflow installed and running: `airflow db init; airflow scheduler &; airflow webserver &`
   - FPL API accessible (https://fantasy.premierleague.com/api/)
   - Understat API key (if using; optional fallback to FPL-only)
   - data/2024-25/ directory with accumulated_gw.csv
   - predictions/2024-25/ directory structure created

3. Execution Workflow
   - Manual trigger (dev): `airflow dags trigger fpl_retrain_schedule`
   - Automatic trigger (production): Airflow scheduler runs on schedule
   - Monitor: Airflow UI → DAGs → fpl_retrain_schedule → Graph View
   - Task flow: collect → validate → retrain → evaluate → export
   - Expected runtime: ~5-10 min (depends on model training)

4. Monitoring
   - Check Airflow logs: airflow logs -d fpl_retrain_schedule -t {task_id}
   - Metrics dashboard (Phase 11+): Track RMSE/MAE/R²/Spearman per GW
   - Alert thresholds:
     - RMSE > baseline × 1.15 → investigate (possible drift)
     - MAE > 0.8 pts/player → log warning
     - R² < 0.80 → consider weekly retrain instead of 2-GW
     - Spearman < 0.85 → ranking quality degraded (impacts captain selection)
   - Task failure: Check logs for API errors, missing data, timeout
   - Recovery: Retry task via Airflow UI or re-trigger DAG

5. Alerts & Recovery
   - Drift detected (2+ GWs >15% RMSE):
     a. Check recent injuries/suspensions (FPL API)
     b. Investigate if fixture difficulty spike
     c. If confirmed structural change: manual retrain (--force-retrain flag)
     d. If false alarm: increase threshold to 20% or decrease retraining frequency
   
   - API failure (FPL or Understat):
     a. Check internet connectivity
     b. FPL API status page: fantasy.premierleague.com
     c. Fallback: Use FPL-only (Understat is optional; log warning)
     d. Retry: Airflow auto-retries 1×; if fails again, escalate
   
   - Model training timeout (>10 min):
     a. Check accumulated_gw.csv size (should be <50 MB)
     b. If bloated, archive old seasons to compressed file
     c. Reduce n_estimators in ensemble (research-tested 500 → 300)
     d. Increase Airflow task timeout
   
   - Prediction export fails (TSV write error):
     a. Check disk space: df -h
     b. Check predictions/ directory permissions: chmod 755
     c. Retry export task manually

6. Maintenance
   - Weekly: Review metrics CSV (tests/results/live_retraining_metrics_2024-25.csv)
   - Monthly: Evaluate if 2-GW frequency appropriate (check stability metric)
   - Season end: Archive trained models, refresh baseline RMSE from next season
   - Phase 11: Add fixture difficulty weighting, injury prediction features

7. FAQ
   - Q: Why not retrain weekly?
     A: Research shows 2-GW frequency optimal (75% cost reduction, <2% accuracy loss)
   
   - Q: What if drift is detected?
     A: Retrain immediately (override scheduled 2-GW). Log cause (injuries? fixture spike?)
   
   - Q: Can I manually force a retrain?
     A: Yes: `python3 -c "from fpl_auto.retrainer import FPLModelRetrainer; r = FPLModelRetrainer(...); r.retrain_on_schedule(gw=X)"`
   
   - Q: How do I validate predictions are correct?
     A: Load predictions/{season}/GW{n}/{pos}.tsv and compare to manager.py output

Save to docs/RETRAINING_RUNBOOK.md with markdown formatting.
